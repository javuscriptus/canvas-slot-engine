# Архитектура

Документ описывает целевое устройство клиента: границы слоёв, контракты между
ними и правила, которые нельзя нарушать. Он же — спецификация для любого, кто
собирается делать на этом движке другую игру.

Сервер описан отдельно в [INTEGRATION.md](INTEGRATION.md); здесь он появляется
только там, где клиент обязан ему не доверять.

---

## Три слоя и одно правило

```
engine/     умеет рисовать, анимировать, слушать ввод. Не знает слово «слот».
slot/       умеет играть в слот. Не знает слово «Сочи».
themes/     знает про Сочи. Не содержит логики.
```

Правило, из которого выводится всё остальное: **зависимости идут только вниз**.
`engine/` не импортирует ничего из `slot/` и `themes/`. `slot/` не импортирует
ничего из `themes/` — тема попадает в него параметром конструктора. Нарушение
этого правила проверяется тестом `client/test/layering.test.js`, а не совестью.

Практический смысл: чтобы выпустить игру на другой теме, нужно добавить каталог
в `themes/` и не трогать ничего больше. Если для новой темы пришлось править
файл в `engine/` или `slot/` — это дефект слоя, а не особенность темы.

`tools/assets/palette.mjs` не объявляет цветов: он переэкспортирует
`themes/sochi/palette.js`. Палитра арта и палитра интерфейса обязаны быть
одним объектом — иначе правка золота в UI молча оставляет символы
прежними, и расхождение накапливается годами, потому что ни один тест
не сравнивает картинку с константой.

## Контракт темы

`themes/<name>/theme.js` экспортирует один объект. Всё, что игра знает о своём
оформлении, лежит в нём — и больше нигде. Ключи, помеченные `обязательно`,
проверяются при старте: игра не поднимется с неполной темой, вместо того чтобы
падать посреди спина на отсутствующем кадре.

```js
export default {
  id: "sochi",                    // обязательно; совпадает с именем каталога
  title: "Сочи · Sunset",

  palette,                        // обязательно; из palette.js — цвета и градиенты
                                  // ключами: stage, backdrop, line, winGlow,
                                  // text*, positive/warn/wild, rowStripe, …

  fonts: {                        // обязательно
    family: "Poppins, Lora, sans-serif",
    numeric: "Poppins, sans-serif",
    mono: "ui-monospace, monospace",
    preload: ["700 32px Poppins", …],     // прогрев до первого кадра

    // РОЛИ надписей. Слот называет роль, тема решает, как она выглядит.
    // Цвета здесь — КЛЮЧИ палитры, а не литералы.
    roles: {
      meterValue: {
        weight: 700, size: 40, family: "numeric",
        gradient: "meterGradient", stroke: "stroke", strokeWidth: 2,
        align: "center", shadow: { color: "shadowSoft", blur: 6, x: 0, y: 2 }
      },
      // … всего 26 ролей: счётчики, баннеры, окна, история, заставка
    }
  },

  timings: {                      // обязательно; секунды, единственное место
    reelSpeed: 26, reelSpeedTurbo: 40,
    reelMinSpin: 0.85, reelStopGap: 0.17, anticipationHold: 1.15,
    winCycleStep: 1.5, bannerIn: 0.45, modalFade: 0.18,
    // … 34 ключа: барабаны, показ выигрыша, баннеры, бонус, автоигра, окна
  },

  atlas: { reelFrame: "reel_frame", winFrame: "win_frame", … },
  sounds: { spinStart: "spin_start", reelStop: "reel_stop", … },
  music: { base: "music_base", free: "music_free" },

  scene: {                        // слои фона, их скорости, персонаж
    layers: [ /* см. «Живая сцена» */ ],
    character: null,
  },

  winTiers: [ /* key, threshold в ставках, banner, sound, duration, shake */ ],
  winMediumThreshold: 5,              // ниже — тихий звук выигрыша, выше — средний
  volatility: { level: 4, of: 5 },    // для заставки: «σ = 7.08» игроку не говорит ничего

  layout,                             // из layout.js: build(vw, vh, {reels, rows})
  strings, symbols,                   // из strings.js
  effects,                            // рецепты частиц
  createBackground, createAmbient,    // фон и живность сцены
};
```

Роль надписи разворачивается в стиль узла `Text` функцией
`slot/theme/styles.js#textStyle(theme, role, scale)`. Слот не собирает строки
шрифтов и не знает названий цветов; масштаб нужен там, где надпись живёт
внутри масштабируемой композиции (заставка, таблица выплат).

`createAmbient` — плагин темы, а не набор колбэков игры:

```js
createAmbient({ app, layer, store, audio, theme, getState })
  -> { applyLayout(layout), destroy() }
```

Ему выдают слой сцены и подписку на кадр, дальше он живёт сам: заводит свои
узлы, сам их двигает, сам решает, когда крикнуть чайке. `getState()` отдаёт
состояние игры общими словами (`{ idle, free }`) — ядро про чаек не знает.

Проверка полноты темы — `slot/theme/validate.js`. Она вызывается один раз при
старте и перечисляет все недостающие ключи сразу, а не по одному за запуск.

## Почему в игровом слое запрещён `ctx`

До переработки барабаны, линии выплат и все оверлеи рисовали себя сами через
узел `Custom(ctx => …)`: 129 прямых обращений к контексту Canvas2D в
`client/src/game/`. Это выглядит удобно ровно до первого вопроса «а можно
то же самое на WebGL» — ответ «нет», потому что игровой слой оказался
написан против конкретного графического API.

Поэтому теперь так: **узел описывает, что нарисовать, бэкенд решает, чем.**
Игровой слой строит узлы (`Sprite`, `AnimatedSprite`, `NineSlice`, `Mesh`,
`ParticleEmitter`), а как они лягут в железо — дело `engine/render/`.

Новый тип узла добавляется регистрацией отрисовщика, а не правкой рендерера:

```js
// engine/render/drawables.js
register(NodeType.SPRITE, {
  canvas2d(ctx, node, ctxState) { … },
  webgl2(batch, node) { … },
});
```

Раньше на этом месте была цепочка `instanceof` внутри `_draw`, и добавить свой
тип узла, не правя движок, было нельзя.

## Живая сцена

Фон — не картинка, а стопка слоёв. Каждый слой знает свою глубину и своё
движение; глубина задаёт и скорость параллакса, и порядок отрисовки.

```js
layers: [
  { key: "sky",      depth: 1.00, motion: { type: "drift", x: 0.4 } },
  { key: "mountains",depth: 0.72, motion: { type: "parallax" } },
  { key: "sea",      depth: 0.55, motion: { type: "wave", amp: 6, period: 7 } },
  { key: "palms",    depth: 0.28, motion: { type: "sway", amp: 0.012, period: 4.3 } },
  { key: "pebbles",  depth: 0.10, motion: null },
]
```

`motion.type` разрешается в функцию из `engine/`; тема не содержит кода
движения, только его параметры. Параллакс реагирует на наклон устройства и на
положение указателя — на десктопе это единственный источник «глубины», которого
не даёт статичная картинка.

Ключевое отличие от прежнего `BackgroundLayer`: тот собирал фон в offscreen и
блитил один к одному, а перерисовывался только по `_dirty`. Такая конструкция
исключает анимацию по построению — не «фон не анимирован», а «фон не может быть
анимирован». Новый `ParallaxScene` рисует слои напрямую и опирается на то, что
бэкенд их пакует; на Canvas2D дальние статичные слои по-прежнему кешируются,
но кеш — это оптимизация внутри слоя, а не архитектура сцены.

## Механика как модуль

Сетка, способ подсчёта выплат и способ подачи результата разделены. `slot/grid.js`
работает с любыми `reels × rows`; механика получает экран и возвращает выигрыши.

```js
// slot/mechanics/lines.js  — 5×3, 20 линий (включено сейчас)
// slot/mechanics/tumble.js — 6×5, каскад, выплаты за скопления
export const mechanic = {
  id: "lines",
  evaluate(screen, bet, config) { return { wins, total }; },
  presentation: "sequential",   // как показывать: по одной линии или каскадом
};
```

Механика выбирается конфигом с сервера (`config.mechanic`), а не сборкой.
Сейчас сервер отдаёт `lines`; математика `tumble` не посчитана и в бою
не используется — модуль существует, чтобы вторая механика включалась
конфигом, а не переписыванием клиента.

**Математика остаётся источником истины на сервере.** Клиентская механика
считает выплаты только для показа и обязана сходиться с присланным сервером
итогом; расхождение — ошибка, которая логируется и не влияет на деньги.

## Чему клиент не верит

Клиент не считает деньги и не решает исходы. Он показывает то, что прислал
сервер, и обязан пережить любой ответ, включая враждебный.

- Адрес API берётся из конфигурации сборки, **не** из параметра URL. Иначе
  `?api=//злой.хост` уводит launch-токен оператора.
- Список origin для `postMessage` приходит с сервера в `/api/config`, не из URL.
- Экран, выданный сервером, рисуется как есть. Если локальная механика
  насчитала другой итог — расхождение уходит в лог, а на экране остаётся
  серверный результат.
- Баланс никогда не вычисляется сложением; он берётся из ответа сервера.

## Производительность: что нельзя делать в кадре

Правила выведены из замеров, а не из принципов. Нарушение каждого из них
однажды стоило кадров.

1. **`ctx.shadowBlur` — никогда.** Свечение приходит готовым спрайтом.
   Баннер крупного выигрыша размером 1644×480 с гауссовым размытием каждый кадр
   стоил 10–20 мс — ровно на самом эффектном месте игры.
2. **`canvas.width = …` — никогда.** Присваивание переаллоцирует буфер и очищает
   холст. `Text` перерисовывается только при смене содержимого и только в холст,
   который уже достаточно велик.
3. **Аллокации в кадре — никогда.** Матрицы, векторы и частицы переиспользуются;
   строковые ключи в горячем цикле не собираются.
4. **Пересборка текстур — вне кадра.** Смена размера окна откладывается и
   выполняется порциями: синхронная пересборка двух десятков символов давала
   100–200 мс замирания на каждый поворот экрана.
5. **Полноэкранная заливка — один раз.** Фон и очистка холста не должны
   покрывать одни и те же пиксели дважды.

Бюджет: 60 fps на Adreno 610 / Mali-G52 при overdraw не выше 4×.

## Рендер-бэкенды

Фасад `render/renderer.js` выбирает бэкенд при старте и держит один и тот же
интерфейс для обоих.

**WebGL2** — основной. Батчит спрайты в один вызов отрисовки, даёт мип-мапы
(и делает ненужным весь код предмасштабирования), аддитивное свечение без
`globalCompositeOperation`, тинт на спрайт без кеша подкрашенных копий,
и пост-обработку через render-to-texture.

**Canvas2D** — запасной, включается при отсутствии WebGL2 и по
`?renderer=canvas2d`. Даёт ту же картинку с упрощениями: без bloom, без
дисторшна, частиц меньше. Игра обязана быть полностью играбельной на нём.

Выбор бэкенда не виден ни игровому слою, ни теме. Тест `client/test/backends.test.js`
рисует одну сцену обоими и сравнивает состав кадра.

## Что проверяется машинно

```bash
node --test "server/test/**/*.test.js"     # математика, деньги, ГПСЧ, тикеты
node --test "client/test/**/*.test.js"     # слои, тема, механики, бэкенды
node tools/preview/capture.mjs --out shots # реальные кадры игры
node tools/preview/smoke.mjs               # загрузка, спин, портрет
node tools/preview/stopstress.mjs          # «Стоп» на всей длине спина
node tools/preview/perf.mjs                # бюджет кадра и драв-коллы
```

`layering.test.js` разбирает импорты и падает, если `engine/` потянул `slot/`,
а `slot/` — `themes/`. Он же ищет в движке и в слоте цвета, гарнитуры и имена
кадров: пока оформление разбросано по коду, вторая тема невозможна физически.
`theme.test.js` прогоняет через `validate.js` КАЖДУЮ тему каталога, строит обе
раскладки и требует, чтобы темы отличались друг от друга палитрой, шрифтами,
темпом и текстами — тема-копия ничего не доказывает.

Это единственная защита от того, что слои снова слипнутся: договорённость,
которую никто не проверяет, живёт около месяца.

Настоящее же доказательство сменяемости — `themes/neon`. Вторая тема
включается параметром `?theme=neon` и не потребовала ни одной правки в
`slot/` и `engine/`; всё, что её отличает, лежит в её каталоге.
